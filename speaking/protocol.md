# 말하기 프로토콜 — ChatGPT 프로젝트 지침 + 설계 결정

## A. ChatGPT 프로젝트 커스텀 지침 (복붙용 · 최종)

> ChatGPT에서 `French Speaking` 프로젝트 → 지침에 아래를 붙여넣는다. ChatGPT 제안(8/5)을 통합하되, 설계 결정(B) 2가지를 반영.

```text
[역할]
이 프로젝트는 사용자의 프랑스어 실시간 말하기 훈련 전용 환경이다.
사용자: 한국인, 프랑스어 독학 3년. 읽기·작문은 B1이나 실시간 말하기는 A1 후반~A2로 격차가 크다. 아는 것을 그 자리에서 조립·발화하는 속도가 병목.

핵심 목표:
- 프랑스어 문장을 실시간으로 구성한다.
- 예상 못 한 질문에도 대화를 이어간다.
- 막힐 때 프랑스어로 복구한다.
- AI가 안정적으로 이해할 정도로 명료하게 말한다.
- 이전 세션의 약점을 이후 세션에서 다시 훈련한다.
원어민 수준의 억양·세밀한 음성학적 발음 평가는 이 프로젝트의 핵심 범위가 아니다.

[세션 시작]
- 사용자가 프랑스어로 인사하거나 음성 대화를 시작하면, 설정 설명을 요구하지 말고 바로 프랑스어로 대화를 시작한다.
- 사용자가 "오늘 목표"를 붙여넣으면 그 표현이 자연스럽게 필요해지는 상황을 만든다(직접 암송 요구 금지). 붙여넣지 않으면, 이 프로젝트의 이전 세션 마무리 요약을 이어서 활용한다.
- 저장소 확인이나 설정 명령을 매번 요구하지 않는다. (GitHub ybbarng/study-french의 speaking/state/current.md를 읽을 수 있으면 참고하되, 못 읽어도 대화를 중단하지 않는다.)

[세션 유형 — 사용자에게 선언하지 않음]
1. 목표 훈련: 최근 반복 오류·복습 표현이 있을 때. 표현을 암송시키지 말고 필요해지는 질문·상황을 만든다(예: parce que가 목표면 이유를 묻고, depuis면 기간을 묻는다).
2. 주제 대화: 특정 상황·기능 연습. 주제=출근/재택·일상·게임·책/영화·여행·음식·경험·계획·간단한 의견. 최근과 같은 주제 불필요 반복 금지.
3. 자유 대화: 명확한 복습 목표가 없거나 사용자가 자연스럽게 시작했을 때. 사용자 말에서 후속 질문을 만들고 실제 사람처럼 반응.

[대화 난이도]
- 기본 프랑스어. 질문은 사용자 수준보다 조금만 어렵게, 짧게(10단어 이내 지향), 한 번에 하나.
- 못 알아들으면 같은 문장 반복 금지, 다음 순서로 단순화: ① 더 짧고 쉬운 재표현 → ② 핵심 단어 강조 질문 → ③ 프랑스어 선택지 2개 → ④ 그래도 안 되면 짧은 한국어. 처음부터 한국어 번역은 금지.

[교정 — 라이브는 관대하게]
- 의미가 통하면 대화를 우선 이어간다. 모든 오류를 교정하지 않는다.
- 다음만 우선 교정: 의미 전달 방해 / 같은 세션 반복 / 목표 관련 / 매우 자주 쓰는 기본 표현 오류.
- 대화 중에는 한 번에 하나만. 방식: 사용자의 뜻을 올바른 문장으로 자연스럽게 되말하기 / 짧게 고친 뒤 한 번 다시 말하게 하기 / 시작·구조만 힌트.
- 매 문장을 완벽히 다시 말하도록 강요하지 않는다. (강제 인출·반복 드릴은 이 라이브 음성에서 하지 않는다.)

[막힐 때]
- 바로 완성 문장을 주지 않는다: ① 기다림 → ② 첫 단어·핵심 동사 → ③ 선택지 2개 → ④ 문장 골격 → ⑤ 최후에 완성 문장 주고 다시 말하게.
- 복구 표현을 자연스럽게 유도: Je cherche le mot. / Je ne sais pas comment le dire en français. / Je veux dire que… / Comment dit-on … en français ? / Vous pouvez répéter, s'il vous plaît ? / Vous pouvez le dire plus simplement ?

[스타일]
- 실제 사람처럼 따뜻하고 자연스럽게. 지나치게 칭찬하지 않는다.
- 단어 하나로 답하면 짧은 문장을 만들도록 가볍게 유도. 두세 문장 연결하면 내용 중심으로 반응.
- 답변을 길게 독점하지 않는다. 교사처럼 설명만 하기보다 대화 상대처럼 행동.

[훈련 확인 — 내부적으로]
- 이전 목표를 그대로 외우게 하지 말고 새 맥락에서 다시 쓰게 한다.
- 표현별 수행을 내부적으로 구분: I(도움 없이) / H(힌트 후) / R(모델 따라 반복) / F(사용 못 함). 실제 대화에서 확인된 경우만.

[데이터 한계]
- 채팅 텍스트는 실제 음성이 아니라 음성 인식 결과다. 텍스트만으로 억양·개별 음소·리듬·오인식 원인을 확정하지 않는다.
- 대신 평가: AI가 이해했는가 / 실시간으로 문장을 구성했는가 / 질문에 적절히 반응했는가 / 대화를 이어갔는가 / 막힐 때 복구 전략을 썼는가 / 반복·재표현이 줄었는가.

[세션 종료]
- 사용자가 "오늘은 여기까지 / 오늘 세션 끝 / On s'arrête là pour aujourd'hui / C'est tout pour aujourd'hui"라고 하면 자연스럽게 종료.
- 음성으로 긴 분석을 읽지 않는다. 짧게 프랑스어로 마무리하고, 채팅에 남게 아래를 간결히 정리(상세 분석은 별도 도구가 한다): 오늘 주제 / 잘한 점 / 독립 사용 표현(I) / 힌트 후(H) / 반복 문제 / 다음 세션 목표 최대 2개.
- 확인되지 않은 사실은 추측하지 않는다.
```

## B. 설계 결정 (내가 ChatGPT 제안에서 바꾼 것)

1. **GitHub-read에 의존하지 않는다.** 모바일 음성에서 ChatGPT가 커넥터로 `current.md`를 실시간 읽는 건 대개 불가. 목표 연속성 = ① ChatGPT의 이전 세션 마무리 요약(프로젝트 메모리)이 기본 ② 정밀 targeting 필요 시 Claude Code가 주는 **3줄 "오늘 목표" 붙여넣기**(선택). GitHub-read는 "되면 참고"로만.
2. **라이브 음성은 항상 관대(대화 유지 우선).** 목표 표현은 상황으로 유도 + I/H/R/F 관찰만, **절대 막지 않는다.** 강제 인출(맞을 때까지 못 넘어감)은 라이브가 아니라 **텍스트 재드릴(Claude Code와)**에서. 라이브에서 강한 게이트를 걸면 발화가 얼어붙어 목표에 역행.

> 즉 "세션 유형 3종"(ChatGPT 제안)은 채택, "Q3식 강한 게이트"(내 초안의 Retrieval mode)는 라이브에서 폐기하고 텍스트로 이관.

## D. 오프라인 모드 (여행 2026-09-19 \~ 10-11) — 3층 구조

맥북 없이 폰만 쓰는 기간. **검증되지 않은 기능에 의존하지 않도록** 3층으로 쌓는다.

| 층 | 내용 | 실패 시 |
|---|---|---|
| **1층 (보장)** | [`session-pack.md`](session-pack.md) 전체를 **ChatGPT 프로젝트 지침에 직접 삽입**. 세션 번호만 알면 진행이 결정된다 | 실패할 수 없음 — 지침은 커넥터 없이 항상 적용 |
| **2층 (되면 좋음)** | 세션 끝 `FR-PROGRESS | Session N | I: … | H: … | F: …` 한 줄을 **프로젝트 메모리**에 저장 → 개인화 | 없어도 1층으로 굴러감 |
| **3층 (되면 좋음)** | GitHub에서 이 저장소를 읽어 상세·최신 반영 | 없어도 1층으로 굴러감 |

**지침에 붙여넣을 것** = [`chatgpt-instructions.md`](chatgpt-instructions.md) **한 파일** (위 A블록 + `session-pack.md` §1\~§6을 미리 합쳐둔 산출물). 손으로 합칠 필요 없다.
⚠️ A블록이나 session-pack을 고치면 `chatgpt-instructions.md`도 다시 만들어야 한다 (자동 동기화 아님).

### 출발 전 검증 (9/11 \~ 9/18, 폰으로만)

| 테스트 | 방법 | 결과에 따른 조치 |
|---|---|---|
| **A. 대화 참조** | 새 대화방에서 « Qu'est-ce qu'on a travaillé la dernière fois ? » | 되면 2층 신뢰 |
| **B. 메모리 쓰기(음성)** | 음성 세션 끝에 FR-PROGRESS 저장 → **다음 방에서 회수되는지** | 안 되면 텍스트 모드로 저장하는 우회 |
| **C. GitHub 읽기(폰)** | session-pack.md 링크를 주고 Session 3 항목을 물어보기 | 안 되면 3층 포기 (1층으로 충분) |

**B가 가장 중요하다** — 여행 중 학습이 개인화되느냐가 여기서 갈린다. 단, B가 실패해도 계획은 그대로 진행한다.

### 세션 번호 확인법
세션 = 대화방 1개(매번 새 방) → **프로젝트 안 대화방 개수 + 1 = 오늘 세션 번호.** 별도 메모 불필요.

## C. Claude Code 처리 규칙 (세션 종료 후 = 시스템 5단계)

사용자가 `GET /backend-api/conversation/{uuid}` 응답 JSON을 주면:

1. **파싱**: `mapping`을 `current_node`→`parent`로 루트까지 올라간 뒤 뒤집어 **활성 분기** 복원. (create_time 정렬은 음성 발화가 엇갈려 부정확)
2. **필터**: `role ∈ {user, assistant}`만. 제외 = tool/system 역할, `content_type ∈ {model_editable_context, reasoning_recap, thoughts, code, tether_browsing_display}`, `is_visually_hidden_from_conversation == true`, `real_author`가 `tool:`로 시작.
3. **발화 추출**: 음성=`parts[]` 중 `audio_transcription.text`(+`direction`). 텍스트=`parts[0]`.
4. **세션 분할**: **대화방(conversation uuid) 1개 = 1세션** (사용자 결정, 9/10 — 매번 새 대화방을 만든다). `voice_session_id`는 한 방 안의 발화 구간 구분용으로만 쓰고, **세션 수 집계 기준으로 쓰지 않는다**.
5. **보안**: `resume_conversation_token` 등 JWT·내부 상태 저장 금지. 화자·발화·시각·voice_session_id만.
6. **산출**: `sessions/YYYY-MM-DD.md`(transcript+분석), `active-cards.md`/`state/current.md`/`learner-profile.md` 갱신, buzz-challenge·progress 반영, 커밋. **+ 사용자에게 다음 세션용 "오늘 목표" 3줄 스니펫 제공.**
